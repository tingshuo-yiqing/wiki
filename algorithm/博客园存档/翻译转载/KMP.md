# 前缀函数与 Knuth-Morris-Pratt 算法

### 前缀函数的定义

给定一个长度为 $n$ 的字符串 $s$。该字符串的**前缀函数**被定义为一个长度为 $n$ 的数组 $\pi$，其中 $\pi[i]$ 是子串 $s[0 \dots i]$ 的最长真前缀的长度，且该前缀同时也是该子串的后缀。字符串的真前缀是指不等于该字符串本身的前缀。根据定义，$\pi[0] = 0$。

数学上，前缀函数的定义可以写成如下形式：
$$
\pi[i] = \max_{k=0 \dots i} \{k : s[0 \dots k-1] = s[i-(k-1) \dots i]\}
$$
例如，字符串 "abcabcd" 的前缀函数是 $[0, 0, 0, 1, 2, 3, 0]$，字符串 "aabaaab" 的前缀函数是 $[0, 1, 0, 1, 2, 2, 3]$。

### 朴素算法 

完全按照前缀函数定义实现的算法如下：

```cpp
vector<int> prefix_function(string s) {
    int n = (int)s.length();
    vector<int> pi(n);
    for (int i = 0; i < n; i++)
        for (int k = 0; k <= i; k++)
            if (s.substr(0, k) == s.substr(i-k+1, k))
                pi[i] = k;
    return pi;
}
```

很容易看出它的时间复杂度是 $O(n^3)$，这还有改进的空间。

### 高效算法

该算法由 Knuth 和 Pratt 提出，Morris 在 1977 年也独立提出了该算法。它被用作子串搜索算法的核心函数。

#### 第一个优化

第一个重要的观察是，前缀函数的值最多只能增加 1。

确实，否则的话，如果 $\pi[i+1] > \pi[i] + 1$，那么我们可以取这个以位置 $i+1$ 结尾、长度为 $\pi[i+1]$ 的后缀，并去掉它的最后一个字符。最终我们会得到一个以位置 $i$ 结尾、长度为 $\pi[i+1] - 1$ 的后缀，它比 $\pi[i]$ 还要大，即我们得到了一个矛盾。

下图展示了这个矛盾。位置 $i+1$ 处最长的真前缀（同时也是后缀）的长度为 4。因此字符串 $s_0 s_1 s_2 s_3$ 等于字符串 $s_{i-2} s_{i-1} s_i s_{i+1}$，这也意味着字符串 $s_0 s_1 s_2$ 和 $s_{i-2} s_{i-1} s_i$ 是相等的，因此 $\pi[i]$ 必须至少为 3。
$$
\underbrace{\overbrace{s_0s_1}^{\pi[i]=2}s_2s_3}_{\pi[i+1]=4}\ldots\underbrace{s_{i-2}\overbrace{s_{i-1}s_i}^{\pi[i]=2}s_{i+1}}_{\pi[i+1]=4}
$$
因此，当移动到下一个位置时，前缀函数的值可以增加 1、保持不变，或者减少某个量。这个事实已经允许我们将算法的复杂度降低到 $O(n^2)$，因为在一步中，前缀函数最多只能增加 1。总的来说，该函数最多只能增加 $n$ 步，因此也最多只能减少 $n$ 步。这意味着我们只需要执行 $O(n)$ 次字符串比较，从而达到 $O(n^2)$ 的复杂度。

#### 第二个优化

让我们更进一步，我们希望摆脱字符串比较。为了实现这一点，我们必须利用在前几步中计算出的所有信息。

因此，让我们计算 $i+1$ 的前缀函数 $\pi$ 的值。如果 $s[i+1] = s[\pi[i]]$，那么我们可以肯定地说 $\pi[i+1] = \pi[i] + 1$，因为我们已经知道位置 $i$ 处长度为 $\pi[i]$ 的后缀等于长度为 $\pi[i]$ 的前缀。这再次用一个例子来说明。

如果情况并非如此，即 $s[i+1] \neq s[\pi[i]]$，那么我们需要尝试一个更短的字符串。为了加快速度，我们希望立即移动到最长的长度 $j < \pi[i]$，使得在位置 $i$ 处的前缀性质仍然成立，即 $s[0 \dots j-1] = s[i-j+1 \dots i]$：

事实上，如果我们找到这样一个长度 $j$，那么我们再次只需要比较字符 $s[i+1]$ 和 $s[j]$。如果它们相等，那么我们可以赋值 $\pi[i+1] = j+1$。否则，我们需要找到小于 $j$ 的最大值，使得前缀性质成立，依此类推。这种情况可能会一直持续到 $j=0$。如果此时 $s[i+1] = s[0]$，我们赋值 $\pi[i+1] = 1$，否则 $\pi[i+1] = 0$。

所以我们已经有了算法的总体框架。剩下的唯一问题是：我们如何有效地找到长度 $j$？让我们回顾一下：对于位置 $i$ 处前缀性质成立的当前长度 $j$，即 $s[0 \dots j-1] = s[i-j+1 \dots i]$，我们希望找到满足前缀性质的最大的 $k < j$。

如图所示，这必定是 $\pi[j-1]$ 的值，我们之前已经计算过了。

#### 最终算法

所以我们最终可以构建一个不执行任何字符串比较、仅执行 $O(n)$ 次操作的算法。

以下是最终的过程：
*   我们通过从 $i = 1$ 到 $i = n-1$ 迭代来循环计算前缀函数 $\pi[i]$ 的值（$\pi[0]$ 刚被赋值为 0）。
*   为了计算当前值 $\pi[i]$，我们设置变量 $j$ 表示前一个字符的最佳后缀长度，初始为 $j = \pi[i-1]$。
*   测试如果长度为 $j+1$ 的后缀也是前缀，这可以通过比较 $s[j]$ 和 $s[i]$ 来完成。如果它们相等，那么我们赋值 $\pi[i] = j+1$，否则我们缩小 $j$ 到 $\pi[j-1]$ 并重复这一步。
*   如果我们达到了长度 $j=0$ 且仍然没有匹配，那么我们赋值 $\pi[i] = 0$ 并进入下一个下标 $i+1$。

#### 代码实现

代码实现极其简短且富有表现力。

```cpp
vector<int> prefix_function(string s) {
    int n = (int)s.length();
    vector<int> pi(n);
    for (int i = 1; i < n; i++) {
        int j = pi[i-1];
        while (j > 0 && s[i] != s[j])
            j = pi[j-1];
        if (s[i] == s[j])
            j++;
        pi[i] = j;
    }
    return pi;
}
```

这是一个**在线（online）**算法，也就是说它可以在数据到达时进行处理——例如，你可以逐个读取字符串字符并立即处理它们，找到每一个新字符的前缀函数值。该算法仍然需要存储字符串本身以及先前计算的前缀函数值，但如果我们预先知道前缀函数在该字符串上能取到的最大值 $M$，我们就可以只存储字符串的前 $M+1$ 个字符以及相同数量的前缀函数值。

### 应用 (Applications)

#### 在字符串中查找子串：Knuth-Morris-Pratt 算法

这个任务是前缀函数的经典应用。

给定一个文本 $t$ 和一个字符串 $s$，我们想要找到并展示 $s$ 在 $t$ 中出现的所有位置。

为了方便起见，我们用 $n$ 表示字符串 $s$ 的长度，用 $m$ 表示文本 $t$ 的长度。

我们构造字符串 $s + \# + t$，其中 $\#$ 是一个既不在 $s$ 中也不在 $t$ 中出现的分隔符。让我们计算这个字符串的前缀函数。现在想想前缀函数的值的含义。除了前 $n+1$ 个条目（属于字符串 $s$ 和分隔符），根据定义，值 $\pi[i]$ 显示了以位置 $i$ 结尾的最长子串且该子串与前缀重合的长度。但在我们的情况下，这无非就是以位置 $i$ 结尾且与 $s$ 匹配的最大子串。这个长度不可能大于 $n$ ，因为遇到了分隔符。如果等式 $\pi[i] = n$ 成立，就意味着字符串 $s$ 在这个位置完整出现了，即它在位置 $i$ 结束。我们只需要计算在原字符串 $s + \# + t$ 中进行索引的对应位置即可。

因此，如果在某个位置 $i$ 有 $\pi[i] = n$，那么在字符串 $t$ 的位置 $i - (n + 1) - n + 1 = i - 2n$ 处，字符串 $s$ 出现了。

正如在前缀函数计算的描述中所提到的，如果我们知道前缀函数的值永远不会超过某个特定值，那么我们就不需要存储整个字符串及它的函数值，而只需要存储它的开头部分。在我们的情况下，这意味着我们只需要存储字符串 $s + \#$ 以及它的前缀函数值。我们可以一次读取文本 $t$ 的一个字符并计算出前缀函数的当前值。

因此，Knuth-Morris-Pratt 算法在 $O(n+m)$ 的时间和 $O(n)$ 的内存中解决了这个问题。

#### 统计每个前缀的出现次数

在这里我们同时讨论两个问题。给定一个长度为 $n$ 的字符串 $s$。在问题的第一个变种中，我们想要统计每个前缀 $s[0 \dots i]$ 在同一字符串中出现的次数。在问题的第二个变种中，给定了另一个字符串 $t$，我们想要统计每个前缀 $s[0 \dots i]$ 在 $t$ 中出现的次数。

首先我们解决第一个问题。考虑在位置 $i$ 处前缀函数 $\pi[i]$ 的值。根据定义，这意味着长度为 $\pi[i]$ 的字符串 $s$ 的前缀在位置 $i$ 结束，且没有比这更长的前缀满足此条件。与此同时，较短的前缀也可能在这个位置结束。我们不难发现，我们之前回答的问题在这里得到了同样的答案：计算前缀函数时的情况。给定一个以位置 $i$ 结尾、长度为 $j$ 的前缀，下一个较小的前缀（同样也是位置 $i$ 的后缀）的长度为 $\pi[j-1]$。因此，在位置 $i$ 结束的所有前缀的长度为 $\pi[i], \pi[\pi[i]-1], \pi[\pi[\pi[i]-1]-1]$ 等等，直到下标变为零。因此，我们可以通过以下方式计算答案。

```cpp
vector<int> ans(n + 1);
for (int i = 0; i < n; i++)
    ans[pi[i]]++;
for (int i = n - 1; i > 0; i--)
    ans[pi[i-1]] += ans[i];
for (int i = 0; i <= n; i++)
    ans[i]++;
```

在这里，对于前缀函数的每个值，我们首先统计它在数组 $\pi$ 中出现的次数，然后计算最终答案：如果知道长度为 $i$ 的前缀精确出现了 $\text{ans}[i]$ 次，那么这个数字必须加到其最长真后缀（同时也作为前缀）的出现次数中。最后，我们还需要对每个结果加 1，因为我们还需要统计原始前缀本身。

现在让我们考虑第二个问题。我们应用来自 Knuth-Morris-Pratt 的做法：我们构造字符串 $s + \# + t$ 并计算其前缀函数。与第一个任务的唯一区别在于，我们只对与字符串 $t$ 相关的那些前缀函数值感兴趣，即对于 $i > n+1$ 的 $\pi[i]$。利用这些值，我们可以执行与第一个任务完全相同的计算。

#### 字符串中不同子串的数量

给定一个长度为 $n$ 的字符串 $s$。我们想要计算在其中出现的不同子串的数量。

我们将迭代地解决这个问题。也就是说，在知道了当前字符串中不同子串的数量后，我们要在末尾添加一个字符后来重新计算这个数量。

设 $k$ 为当前字符串 $s$ 中不同子串的数量，我们在末尾添加字符 $c$ 得到 $s+c$。显然，一些新的子串将以 $c$ 结尾。我们想要计算这些以前没有出现过的新子串的数量。

我们取字符串 $t = s + c$ 并反转它。现在任务转换为计算有多少前缀是不在其他地方出现的。如果我们计算反转后的字符串 $t$ 的前缀函数的最大值 $\pi_{\max}$，那么在别处出现的最长前缀的长度即为 $\pi_{\max}$。显然，更短的前缀也一定在其中。

因此，当添加一个新字符 $c$ 时出现的新子串数量为 $|s| + 1 - \pi_{\max}$。

因此，对于每个添加的字符，我们可以在 $O(|s|)$ 的时间内计算出新的子串数量，这就给出了 $O(n^2)$ 总时间复杂度的算法。

值得注意的是，我们也可以通过在开头添加字符，或通过在开头或结尾删除字符来计算不同子串的数量。

#### 压缩字符串

给定一个长度为 $n$ 的字符串 $s$。我们希望找到该字符串的最短“压缩”表示，即我们希望找到一个长度最短的字符串 $t$，使得 $s$ 可以表示为 $t$ 的一个或多个副本的拼接。

显然，我们只需要找到 $t$ 的长度。知道了长度，问题的答案就是 $s$ 中该长度的前缀。

让我们计算 $s$ 的前缀函数。利用其最后一个值，我们定义值 $k = n - \pi[n-1]$。我们将证明，如果 $k$ 整除 $n$，那么 $k$ 就是答案，否则不存在有效的压缩，答案就是 $n$。

假设 $n$ 可以被 $k$ 整除。那么字符串可以被划分为长度为 $k$ 的块。根据前缀函数的定义，长度为 $n - k$ 的前缀将等于其后缀。这意味着最后一个块等于倒数第二个块。而倒数第二个块必须等于在它之前的块。以此类推。结果表明，所有的块都是相等的，因此我们可以将字符串 $s$ 压缩为长度为 $k$。

当然，我们仍然需要证明这实际上是最优的。事实上，如果存在一个小于 $k$ 的更优的压缩方案，那么字符串末尾的前缀函数将大于 $n - k$。因此 $k$ 实际上就是答案。

现在假设 $n$ 不能被 $k$ 整除。我们将证明这意味着答案只能是 $n$。我们通过反证法来证明它。假设存在这样一个答案，且其压缩的长度为 $p$（$p$ 整除 $n$）。那么最后一个前缀函数的值必须大于 $n - p$，即后缀将部分覆盖前缀。现在考虑字符串的前两个块。由于前缀等于后缀，且前缀块与后缀块重合，且它们彼此的相对位移 $k$ 不整除块长度 $p$（否则 $k$ 将整除 $n$），那么块中的所有字符都必须相同。换句话说，字符串仅由一个重复了一遍又一遍的字符组成，因此我们可以将其压缩为大小为 1 的块，这给出 $k=1$，且 $k$ 整除 $n$。产生矛盾。

#### 根据前缀函数构建自动机

让我们回到通过分隔符连接两个字符串的问题，即对于字符串 $s$ 和 $t$，我们计算字符串 $s + \# + t$ 的前缀函数。显然，由于 $\#$ 是分隔符，前缀函数的值永远不会超过 $|s|$。因此，为了计算前缀函数，只需存储字符串 $s + \#$ 及其前缀函数值即可，对于后续的每个字符，我们可以如下计算：

事实上，在这种情况下，知道下一个字符 $c \in t$ 和前一个位置的前缀函数值，就足以计算前缀函数的下一个值，而无需使用字符串 $t$ 的任何以前的字符以及它们的前缀函数值。

换句话说，我们可以构造一个**自动机**（有限状态机）：它的状态是前缀函数的当前值，从一个状态到另一个状态的转移将通过下一个字符来执行。

因此，即使没有字符串 $t$，我们也可以使用与计算转移表相同的算法来构造这样一个转移表 $(\text{old}\_\pi, c) \rightarrow \text{new}\_\pi$：

```cpp
void compute_automaton(string s, vector<vector<int>>& aut) {
    s += '#';
    int n = s.size();
    vector<int> pi = prefix_function(s);
    aut.assign(n, vector<int>(26));
    for (int i = 0; i < n; i++) {
        for (int c = 0; c < 26; c++) {
            int j = i;
            while (j > 0 && 'a' + c != s[j])
                j = pi[j-1];
            if ('a' + c == s[j])
                j++;
            aut[i][c] = j;
        }
    }
}
```

然而在这种形式下，对于小写英文字母，该算法在 $O(n^2 26)$ 的时间内运行。请注意，我们可以应用动态规划并利用表中已计算好的部分。每当我们从值 $j$ 回退到值 $\pi[j-1]$ 时，我们实际上是指转移 $(j, c)$ 通向与转移 $(\pi[j-1], c)$ 相同的状态，并且该答案已经被精确计算出来了。

```cpp
void compute_automaton(string s, vector<vector<int>>& aut) {
    s += '#';
    int n = s.size();
    vector<int> pi = prefix_function(s);
    aut.assign(n, vector<int>(26));
    for (int i = 0; i < n; i++) {
        for (int c = 0; c < 26; c++) {
            if (i > 0 && 'a' + c != s[i])
                aut[i][c] = aut[pi[i-1]][c];
            else
                aut[i][c] = i + ('a' + c == s[i]);
        }
    }
}
```

结果，我们在 $O(26n)$ 的时间内构造了自动机。

这样的自动机什么时候有用？回想一开始，我们使用字符串 $s + \# + t$ 的前缀函数，其目的主要只有一个：寻找字符串 $s$ 在字符串 $t$ 中的所有出现。

因此，这种自动机最明显的好处是**加速计算字符串 $s + \# + t$ 的前缀函数**。通过为 $s + \#$ 构建自动机，我们不再需要存储字符串 $s$ 及其前缀函数值。所有的转移都已经计算并在表中了。

但是还有第二个不太明显的应用。当字符串 $t$ 是一个**使用某些规则构建的巨大字符串**时，我们可以使用自动机。例如这可以是格雷字符串（Gray strings），或者是从输入中通过几个短字符串的递归组合构成的字符串。

为了完整起见，我们将解决这样一个问题：给定一个数字 $k \le 10^5$ 和一个长度 $\le 10^5$ 的字符串 $s$。我们必须计算 $s$ 在第 $k$ 个格雷字符串中的出现次数。回想一下格雷字符串的定义如下：

$g_1 = \text{"a"}$
$g_2 = \text{"aba"}$
$g_3 = \text{"abacaba"}$
$g_4 = \text{"abacabadabacaba"}$

在这种情况下，由于其天文数字般的长度，甚至构造字符串 $t$ 都是不可能的。第 $k$ 个格雷字符串的长度为 $2^k-1$ 个字符。但是，只要知道字符串起始处前缀函数的值，我们就可以有效地计算出字符串末尾前缀函数的值。

除了自动机本身之外，我们还计算值 $G[i][j]$ ——自动机从状态 $j$ 开始处理字符串 $g_i$ 之后的状态值。此外，我们还计算值 $K[i][j]$ ——在处理 $g_i$ 时（从状态 $j$ 开始），$s$ 在 $g_i$ 中出现的次数。实际上 $K[i][j]$ 是在执行操作期间前缀函数取值为 $|s|$ 的次数。那么该问题的答案就是 $K[k][0]$。

我们如何计算这些值？首先，基本值为 $G[0][j] = j$ 和 $K[0][j] = 0$。而所有后续值都可以利用前一个值和自动机来计算。为了计算某个 $i$ 的值，我们回顾字符串 $g_i$ 是由 $g_{i-1}$、字母表中的第 $i$ 个字符和 $g_{i-1}$ 组成的。因此自动机将进入以下状态：

$$\text{mid} = \text{aut}[G[i-1][j]][i]$$

$$G[i][j] = G[i-1][\text{mid}]$$

对于 $K[i][j]$ 的值，也很容易被计算出来：

$$K[i][j] = K[i-1][j] + (\text{mid} == |s|) + K[i-1][\text{mid}]$$

因此我们可以解决格雷字符串的问题，类似地也可以解决大量其他类似问题。例如，使用完全相同的方法也可以解决以下问题：给定一个字符串 $s$ 和一些模式串 $t_i$，其中每个模式串的定义如下：它是一个由普通字符组成的字符串，并且可能包含先前字符串形式为 $t_k^{\text{cnt}}$ 的递归插入，这意味着在这个地方我们必须将字符串 $t_k$ 插入 $\text{cnt}$ 次。此类模式的示例：

$t_1 = \text{"abdeca"}$
$t_2 = \text{"abc"} + t_1^{30} + \text{"abd"}$
$t_3 = t_2^{50} + t_1^{100}$
$t_4 = t_2^{10} + t_3^{100}$

递归替换会使字符串极速膨胀，使得它们的长度可以达到 $100^{100}$ 的数量级。

我们必须计算字符串 $s$ 在每个字符串中出现的次数。

通过构建前缀函数的自动机，然后利用先前的结果计算每个模式的转移，同样可以解决该问题。
